# 주야간보호센터 돌봄 밀도 비교

> **요양보호사 한 명이 어르신 몇 분을 돌보는지**로 전국 주야간보호센터를 비교하는 한 장짜리 웹페이지.
> 공공데이터 **1종**만 사용. 서버·인터넷 없이 HTML 파일 하나로 동작합니다.

```
build/index.html  ← 더블클릭해도 열리고, build/ 폴더를 그대로 올리면 휴대폰으로 열리는 공개 주소가 됩니다
돌봄밀도.html     ← 같은 파일 (로컬 확인용)
```

---

## 1. 누구의, 어떤 불편인가

| | |
|---|---|
| **대상** | **보호자** — 타지에 사는 50대 자녀. 부모님은 지방에 혼자 계신다 |
| **불편** | **"부모님 보낼 주야간보호센터가 동네에 수십 곳인데, 뭘 보고 골라야 할지 모르겠다."** |

장기요양 등급을 받고 나면 기관은 보호자가 **직접** 골라야 합니다. 그런데

- 서울만 523곳, 경기 1,130곳입니다. 한 구에도 수십 곳씩 있습니다
- 지도앱은 **위치와 사진**만 보여줍니다. 고를 근거가 없습니다
- 기관 홈페이지는 전부 "가족같은 분위기", "정성을 다하는" 같은 말뿐입니다
- 결국 **가까운 순서로 찍거나, 남의 말을 듣고** 정합니다

**정답을 골라주는 게 아니라, 비교할 수 있는 숫자 하나를 주는 것**이 이 서비스의 목표입니다.

## 2. 무엇을 보여주는가

시·도 → 시·군·구를 고르면, 그 지역 주야간보호센터가 **요양보호사 1인당 어르신 수가 적은 순**으로 나옵니다.

```
요양보호사 1인당 어르신 수 = 정원 ÷ 요양보호사 수
```

| 순위 | 기관명 | 1인당 | 근거 |
|---|---|---|---|
| 1 | 가가호호 데이케어센터 | **1.9명** | 정원 21 ÷ 요양보호사 11 |
| 2 | 효·보살핌데이케어센터 | **3.6명** | 정원 36 ÷ 요양보호사 10 |

각 기관마다 **해당 시·도 중앙값과 나란히** 보여줍니다. `서울특별시 중앙값 4.8명보다 적습니다`
숫자 하나만으로는 좋은지 알 수 없기 때문입니다. 카드마다 **중앙값 눈금이 있는 막대**로도 같은 비교를 보여줍니다.

그 밖에 **기관명으로 찾기** 칸(들어본 기관이 그 지역에서 몇 위인지), **중앙값보다 적은 곳만** 체크(필터), **결과 링크 복사**(주소에 지역이 붙어 `…/#서울특별시/관악구` — 형제에게 보내면 같은 목록), **마지막 선택 지역 기억**(브라우저에만 저장), 카드마다 **공단 포털 바로가기**(이용가능·평가등급은 거기서)가 있습니다.

### 왜 이 숫자인가

**돌봄의 밀도입니다.** 요양보호사 1명이 2명을 보는 곳과 10명을 보는 곳은 다를 수밖에 없습니다.
전국 실측 범위는 **1.67명 ~ 91.0명**으로 변별력이 충분합니다.

그런데 **이 기준으로 기관을 줄 세워 비교할 수 있는 곳이 없습니다.** 공단 장기요양보험 포털도
평가등급순·거리순·정원 구간 필터는 제공하지만 **인력 규모로는 정렬하지 못합니다.**

### 평가등급과 겹치지 않나 — 실측 대조

`15104801 장기요양기관 평가 결과`를 내려받아 주야간보호 **3,243곳**을 대조했습니다.
*(경쟁 분석용이며 서비스에는 사용하지 않습니다.)*

| 항목 | 값 |
|---|---:|
| 평가총점 ↔ 1인당 수치 상관계수 | **−0.178** (거의 무관) |
| A등급 814곳의 1인당 범위 | **2.80 ~ 17.50명 (6배)** |
| A등급인데 1인당은 전체 중앙값보다 나쁜 곳 | **44.1%** |
| D·E등급인데 1인당은 전체 중앙값보다 좋은 곳 | **40.7%** |
| 평가 결과 보유 기관 비율 | 59.6% (최신 평가 2024-11) |

> **A등급만 보고 고르면 열에 넷은 인력이 평균 이하인 곳을 고르게 됩니다.**
> 평가등급은 5개 영역을 묶은 종합 등급이라 "인력이 충분한가"에는 답하지 않습니다.
> **대체가 아니라 보완입니다.**

## 4. 만들면서 확인한 것

### 4-1. 데이터에 없었던 두 칸

처음 기획은 *"지금 자리가 있는 곳"* 을 찾아주는 것이었습니다. 파일을 열어보니 **불가능**했습니다.

| 기대 | 실제 |
|---|---|
| **현원** | 입소인원 시트는 **정원만** 있습니다. 포털 설명의 *"현원(2025.4월 이전자료)"* 는 현재 파일에 미수록 |
| **전화번호** | 일반현황 10개 칸 어디에도 없습니다 → **기관명 검색 링크**로 대체 |

그래서 불편 정의를 *"자리 있는 곳을 모른다"* → *"뭘 보고 골라야 할지 모른다"* 로 바꾸고,
핵심 지표를 **인력현황 시트**를 활용한 1인당 어르신 수로 교체했습니다.

### 4-2. 조인 함정 — 방문요양 인력이 섞여 들어온다

첫 프로토타입에서 1위가 **1인당 0.25명**으로 나왔습니다. 말이 안 되는 값이었습니다.

입소인원·인력현황 모두 `(기관코드, 기관유형코드)` 단위인데 **기관코드만으로 결합**해서,
같은 기관의 **방문요양 요양보호사 115명**이 주야간보호에 붙은 것이었습니다.

→ **두 키로 결합**하도록 수정. 서울 1위가 1.91명으로 정상화됐습니다.

### 4-3. 갓 문을 연 기관은 이 지표에서 불리하다 — 보정

수치가 가장 높은 5곳이 모두 **요양보호사 1명 / 정원 72~91명**이었습니다.

원본 행을 열어보니 **전원 2026-06-01 지정** — 자료 기준일 9일 전에 문을 연 기관이었습니다.
전국으로 검정하니 단조 감소가 확인됐습니다.

| 개원 후 경과 | 기관수 | 1인당 중앙값 | 20명 초과 비율 |
|---|---:|---:|---:|
| 0~2개월 | 70 | **11.00명** | **34.3%** |
| 2~6개월 | 186 | 9.00명 | 16.1% |
| 6~12개월 | 291 | 8.00명 | 5.2% |
| 1~3년 | 1,075 | 7.00명 | 2.6% |
| 3~10년 | 2,749 | 6.25명 | 1.2% |
| 10년 이상 | 1,067 | 6.20명 | **0.6%** |

**데이터가 잘못된 것이 아니라, 지표가 신규 기관에 불리한 구조입니다.** 정원은 인가받은 최대치인데
신규 기관은 인력을 채우는 중이라 불리하게 나옵니다. 돌봄이 나쁜 게 아닙니다.

**조치**

1. 개원 12개월 미만 **537곳에 설명 배지 표시** — 숨기지 않고 왜 불리한지 적음
2. **중앙값을 운영 1년 이상 기관만으로 재계산** — 서울 5.0→**4.8**, 세종 8.0→**7.5**, 전국 6.56→**6.40**
3. 푸터에 근거 수치 명시

## 6. 한계 — 숨기지 않고 화면에도 적었습니다

1. **돌봄 품질을 보증하지 않습니다.** 비교의 출발점일 뿐입니다
2. **정원은 실제 이용 인원이 아닙니다.** 등록 가능한 최대 인원입니다
3. **요양보호사 수는 기관이 신고한 값**입니다. 신고 시점과 현재가 다를 수 있습니다
4. **자료는 반기마다 갱신**됩니다. 기준일은 2026-06-10, 차기 등록 예정일은 2027-01-29입니다
5. **개원 1년 미만 기관은 불리하게 나옵니다.** 배지로 표시했습니다
6. 정원 또는 요양보호사가 신고되지 않은 **360곳은 순위에서 제외**했습니다

## 7. 재현 방법

```bash
pip install pandas openpyxl

python tools/build_data.py data/ltc_20260610.xlsx data/day_care.json
python tools/build_html.py data/day_care.json build/index.html
python tools/verify_screen.py build/index.html data/ltc_20260610.xlsx   # 화면 ↔ 원본 전수 대조
```

원본 XLSX에서 최종 HTML까지 **두 줄로 재생성**되고, 세 번째 줄이 결과를 원본과 전수 대조합니다.

### 파일 구성

```
build/
  index.html           최종 결과물 (자체완결) — 배포는 이 폴더만
  data.json            전처리 결과 (강의 구조에 맞춰 둠 · 화면은 같은 데이터를 내장해 읽음)
돌봄밀도.html          build/index.html 과 같은 파일 (로컬 확인용)
PLAN.md                심사용 문서 — 1~6번은 강의록 템플릿(5문장·범위·화면·데이터 대응표·변경 이력·검증 기록), 그 아래 상세 부록
CLAUDE.md              Code 탭 작업 규칙 (PLAN.md 근거 · 인증키 금지)
README.md              이 문서
웹서비스_기획서.md/.pdf 기획서 상세
발표슬라이드.html      발표용 8장 (방향키) · 발표자료.pdf 가 제출용 출력본
발표_스크립트.md       3분 대본 · 예상질문 · 점검표

data/
  ltc_20260610.xlsx    공공데이터포털 원본 (무가공)
  day_care.json        전처리 결과 (전국 5,346곳)
  eval_20260625.csv    평가 결과 (비교 분석용 · 서비스 미사용)

tools/
  build_data.py        원본 → JSON          (전처리 본체)
  build_html.py        JSON → HTML          (화면 생성)
  verify_screen.py     화면 숫자 ↔ 원본 전수 대조 (빌더 코드 미재사용)
  peek_xlsx.py         시트·헤더 확인
  check_ltc.py         결측률·조인율 검증
  proto_rank.py        순위 프로토타입
  verify_pick.py       검증 대상·이상치 추출
  verify_rows.py       특정 기관 원본 행 조회
  verify_newly.py      개원 시점 ↔ 지표 관계 검정
  check_eval.py        평가 결과 데이터 구조 확인 (비교 분석용)
  check_vs_eval.py     평가등급 ↔ 1인당 지표 대조 (비교 분석용)
```

## 8. 기술

| 용도 | 선택 | 이유 |
|---|---|---|
| 전처리 | Python + pandas + openpyxl | 공공데이터 XLSX 처리 |
| 화면 | **단일 HTML + 내장 JSON + 바닐라 JS** | 서버 없이 선택·정렬이 실제 동작. 프레임워크 학습비용 0 |
| 배포 | Cloudflare Pages 직접 업로드 (`build/` 폴더) | 휴대폰으로 열리는 공개 주소. 파일 하나라 로컬 더블클릭으로도 동일 동작 → 시연 실패 위험 제거. 인증키 없음 |
