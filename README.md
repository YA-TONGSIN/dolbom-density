# 주야간보호센터 돌봄 밀도 비교

> **요양보호사 한 명이 어르신 몇 분을 돌보는지**로 전국 주야간보호센터를 비교하는 한 장짜리 웹페이지.
> 공공데이터 **1종** 사용 (국민건강보험공단 장기요양기관 시설별 현황 · 15124763). 서버 없이 HTML 파일 하나로 동작합니다.

```
build/index.html  ← 더블클릭해도 열리고, build/ 폴더를 그대로 올리면 휴대폰으로 열리는 공개 주소가 됩니다
돌봄밀도.html     ← 같은 파일 (로컬 확인용)
```

## 1. 누구의, 어떤 불편인가

| | |
|---|---|
| **대상** | **보호자** — 타지에 사는 50대 자녀. 부모님은 지방에 혼자 계신다 |
| **불편** | **"부모님 보낼 주야간보호센터가 동네에 수십 곳인데, 뭘 보고 골라야 할지 모르겠다."** |

장기요양 등급을 받고 나면 기관은 보호자가 **직접** 골라야 합니다. 그런데

- 서울만 526곳, 경기 1,153곳입니다. 한 구에도 수십 곳씩 있습니다
- 지도앱은 **위치와 사진**만 보여줍니다. 고를 근거가 없습니다
- 기관 홈페이지는 전부 "가족같은 분위기", "정성을 다하는" 같은 말뿐입니다
- 결국 **가까운 순서로 찍거나, 남의 말을 듣고** 정합니다

**정답을 골라주는 게 아니라, 비교할 수 있는 숫자 하나를 주는 것**이 이 서비스의 목표입니다.

## 2. 무엇을 보여주는가

시·도 → 시·군·구를 고르면, 그 지역 주야간보호센터가 **요양보호사 1인당 어르신 수가 적은 순**으로 나옵니다.

```
요양보호사 1인당 어르신 수 = 정원 ÷ 요양보호사 수
```

| 순위 | 기관명 | 1인당 | 근거 |
|---|---|---|---|
| 1 | 가가호호 데이케어센터 | **1.9명** | 정원 21 ÷ 요양보호사 11 |
| 2 | 효·보살핌데이케어센터 | **3.6명** | 정원 36 ÷ 요양보호사 10 |

각 기관마다 **해당 시·도 중앙값과 나란히** 보여줍니다. `서울특별시 중앙값 4.8명보다 적습니다`
숫자 하나만으로는 좋은지 알 수 없기 때문입니다. 카드마다 **중앙값 눈금이 있는 막대**로도 같은 비교를 보여줍니다.

그 밖에 **내 동네 먼저**(시·군·구 선택 후 읍면동을 고르면 같은 동 기관이 위로 — 좌표가 없어 거리 대신 동 단위), **기관명으로 찾기** 칸(들어본 기관이 그 지역에서 몇 위인지), 걸러보기 토글 **중간값보다 적은 곳만** · **요양보호사 3명 이상만** · **비용 함께 보기**(등급별 재가급여 월 한도액 상수표 — 공공데이터셋이 아니고 순위에 쓰지 않음), **결과 링크 복사**(주소에 지역이 붙어 `…/#서울특별시/관악구` — 형제에게 보내면 같은 목록), **마지막 선택 지역 기억**(브라우저에만 저장)이 있습니다. 카드의 행동은 **검색하기 · 주소 복사 · 공단 포털에서 직접 찾기**(이용가능·평가등급·전화번호는 거기서) 세 가지입니다.

### 왜 이 숫자인가

**돌봄의 밀도입니다.** 요양보호사 1명이 2명을 보는 곳과 10명을 보는 곳은 다를 수밖에 없습니다.
전국 실측 범위는 **1.67명 ~ 91.0명**으로 변별력이 충분합니다.

그런데 **이 기준으로 기관을 줄 세워 비교할 수 있는 곳이 없습니다.** 공단 장기요양보험 포털도
평가등급순·거리순·정원 구간 필터는 제공하지만 **인력 규모로는 정렬하지 못합니다.**

### 평가등급과 겹치지 않나 — 실측 대조 (분석 기록)

`15104801 장기요양기관 평가 결과`를 내려받아 기관코드로 조인해 **대조 분석**했습니다.
*(10-12에 경쟁 분석용으로만 받았고, 10-13~14 오전에 서비스 화면에 병기했다가 **규칙(원본 공공데이터셋 1개)에 맞춰 10-14에 뺐습니다.** 지금 화면에는 평가등급이 없습니다. 아래는 그 분석 결과입니다.)*

| 항목 | 값 |
|---|---:|
| 평가총점 ↔ 1인당 수치 상관계수 | **−0.179** (거의 무관) |
| A등급 **800곳** 중 1인당이 전국 중간값보다 나쁜 곳 | **328곳 · 41.0%** |
| D·E등급 **499곳** 중 1인당이 전국 중간값보다 좋은 곳 | **218곳 · 43.7%** |
| 등급별 1인당 중앙값 (A / B / C / D / E) | 6.00 / 6.00 / 6.67 / 6.67 / 7.00 |
| 평가 결과 보유 기관 비율 | **59.7%** · 3,190곳 (최신 평가 2024-11) |

> **A등급만 보고 고르면 열에 넷은 인력이 중간값보다 부족한 곳을 고르게 됩니다.**
> 평가등급은 5개 영역을 묶은 종합 등급이라 "인력이 충분한가"에는 답하지 않습니다.
> **대체가 아니라 보완입니다.** 데이터 1개 규칙 안에서는 등급을 화면에 함께 실을 수 없어서,
> 카드마다 **「공단 포털에서 직접 찾기」** 링크로 공단 평가등급을 바로 확인하게 했습니다.

## 4. 만들면서 확인한 것

### 4-1. ①에 없었던 두 칸

처음 기획은 *"지금 자리가 있는 곳"* 을 찾아주는 것이었습니다. 파일을 열어보니 **불가능**했습니다.

| 기대 | 실제 |
|---|---|
| **현원** | 입소인원 시트는 **정원만** 있습니다. 포털 설명의 *"현원(2025.4월 이전자료)"* 는 현재 파일에 미수록 → **끝까지 확보하지 못했습니다** |
| **전화번호** | 일반현황 10개 칸 어디에도 없습니다 → **기관명 검색 링크(「검색하기」)** 로 대체했습니다. 10-14 새벽 상세정보 조회 API(`15058856`)로 5,270곳(98.6%)의 번호를 붙였다가, **데이터 1개 규칙에 맞춰 10-14 오전에 뺐습니다.** 지금은 다시 검색 링크 + 「주소 복사」 + 공단 포털 링크이고, 카드의 전화 아이콘은 누르면 "이 공공데이터에는 전화번호가 제공되지 않습니다. 「검색하기」로 확인하세요." 안내만 합니다 |

그래서 불편 정의를 *"자리 있는 곳을 모른다"* → *"뭘 보고 골라야 할지 모른다"* 로 바꾸고,
핵심 지표를 **인력현황 시트**를 활용한 1인당 어르신 수로 교체했습니다.

### 4-2. 조인 함정 — 방문요양 인력이 섞여 들어온다

첫 프로토타입에서 1위가 **1인당 0.25명**으로 나왔습니다. 말이 안 되는 값이었습니다.

입소인원·인력현황 모두 `(기관코드, 기관유형코드)` 단위인데 **기관코드만으로 결합**해서,
같은 기관의 **방문요양 요양보호사 115명**이 주야간보호에 붙은 것이었습니다.

→ **두 키로 결합**하도록 수정. 서울 1위가 1.91명으로 정상화됐습니다.

### 4-3. 갓 문을 연 기관은 이 지표에서 불리하다 — 보정

수치가 가장 높은 5곳이 모두 **요양보호사 1명 / 정원 72~91명**이었습니다.

원본 행을 열어보니 **다섯 중 셋이 2026-06-01 지정**(자료 기준일 9일 전), **하나가 2026-05-01 지정**(40일 전)이었습니다. (나머지 1곳은 2014년 지정 기관으로, 같은 시설이 기관코드 2개로 중복 등록된 건입니다.)
전국으로 검정하니 단조 감소가 확인됐습니다.

| 개원 후 경과 | 기관수 | 1인당 중앙값 | 20명 초과 비율 |
|---|---:|---:|---:|

| 2~6개월 | 187 | 9.00명 | 16.0% |

**데이터가 잘못된 것이 아니라, 지표가 신규 기관에 불리한 구조입니다.** 정원은 인가받은 최대치인데

6. 정원 또는 요양보호사가 신고되지 않은 **313곳은 순위에서 제외**했습니다 (정원 0/빈값 55곳 + 요양보호사 0/빈값 311곳, 둘 다 해당 53곳 — 겹치는 곳을 한 번만 셈)

## 8. 기술

| 용도 | 선택 | 이유 |
|---|---|---|
| 전처리 | Python + pandas + openpyxl | 공공데이터 XLSX 처리 |
